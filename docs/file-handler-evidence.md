# File native evidence

`tools/ghidra_run.sh DecompileFileHandlers.java` checks the executable MD5 and writes the stock decompilation to `local/census/DecompileFileHandlers.log`. Confirm the log contains `FILE_HANDLERS_DECOMPILE_OK`: Ghidra headless can return success after a script error. The Ghidra MCP identified the loaded program as `StreetLegal_Redline.bak.exe`, MD5 `e686099e7233bb7d7c461b1b35c5064c`.

The native at `00485440` retrieves the file name from the script object and its native pointer. It closes a previously open handle, sets the requested mode, and in mode 0 opens the path for reading. For recognized SDAT types it reads footer records and then seeks to byte 8. It stores the native pointer in the script object and returns whether opening succeeded. Mode 1 creates a file and writes an eight-byte header. Invalid modes report an error. This reading does not establish all failure semantics or resource registration behavior.

The native at `00485b70` reads four bytes from the file handle and returns them as an integer; `00485c10` reads four bytes as a float. Both return a zero value when the object has no native field. If a native field exists but its handle is zero, the decompiler shows an uninitialized return value. The read-only host code deliberately reports an error in such unsupported cases rather than asserting parity. `00485870` closes the file, handles the write footer, frees native state, and clears the script field. These routines remain unmarked in the native audit: the host file reader has not yet been connected to the real script calls and does not implement the complete behaviors.

The installed `Config.loadConfig` tree also calls `File.open` dynamically: nodes 13–20 select local 3, use the string `open`, and pass one integer argument. The stock dispatcher constructs the argument signature `(I)` for name lookup; the resolved declaration supplies `(I)I` for the native handler. `docs/natives_called.tsv` lists this method as uncalled because its census only sees direct method references. The dynamic path is evidence that the 214 direct-reference count is not a complete runtime set.
