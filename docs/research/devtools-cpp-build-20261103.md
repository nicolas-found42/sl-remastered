## Confirmed repository state

- [CMakeLists.txt](../../CMakeLists.txt) already requires CMake 3.20, native arm64, C++20 without extensions, SDL3 3.4.0 CONFIG, JPEG and PNG. It exports compilation commands and applies `-Wall -Wextra -Wshorten-64-to-32 -ffp-contract=off`. Preserve these; this is not a project missing CMake, warnings or numerical controls.
- [CMakePresets.json](../../CMakePresets.json) has Ninja Release and Debug configure/build/test presets, but puts their databases in `build/preset-release` and `build/preset-debug`. [tools/guardrails.py](../../tools/guardrails.py) hardcodes `build/compile_commands.json`, and [README.md](../../README.md) teaches the independent `build` configuration. Thus configuring a documented preset does not by itself satisfy the lint path contract. CMake emits actual translation-unit compiler calls, and export supports Ninja and Makefile generators. [CMake database documentation](https://cmake.org/cmake/help/latest/variable/CMAKE_EXPORT_COMPILE_COMMANDS.html)
- [.clang-format](../../.clang-format) and [.clang-tidy](../../.clang-tidy) exist. Tidy enables three focused checks. The guardrail formats the **entire staged file in memory** and compares bytes, never rewrites. Therefore touching one line in an historically unformatted file can block a commit until unrelated lines are reformatted, conflicting with the no-unrelated-reformat guidance in [CODING_STANDARDS.md](../../CODING_STANDARDS.md). This is a confirmed policy/mechanics conflict; no repository-wide formatting census was run.
- Python syntax is checked on Git index bytes. C/C++ formatting also uses index bytes, then tidy requires working bytes to equal the index. This deliberate partial-staging refusal prevents linting a different main-file revision, but tidy still reads included headers and configuration from the worktree. It does not establish a fully staged source tree. Base mode reads HEAD bytes then applies the same worktree equality rule. [guardrail implementation](../../tools/guardrails.py), [existing controls](../../tests/guardrails_test.py)
- Every changed `.h/.hpp/.c/.cpp/.m/.mm` is sent directly to tidy with the same database. There is no exact-entry coverage preflight or explicit header-to-includer resolution in the wrapper. HeaderFilterRegex controls emitted header diagnostics; it does not create compile commands or select dependent translation units. [Clang-Tidy options](https://clang.llvm.org/extra/clang-tidy/)
- Existing local database has 1,074 entries. Comparing tracked C/C++/Objective-C source paths to it found 101 missing, including `experiments/pointer_width/probe.cpp`, `experiments/wheel_compare/compare.cpp`, many ad hoc native probes, and Wine helper C files. This count describes local metadata, which may be stale; it is not a regeneration result. Those files need explicit supported lint handling, not assumed native flags. Headers normally lack independent commands; clangd borrows includer commands or uses filename heuristics. [clangd compile-command design](https://clangd.llvm.org/design/compile-commands)
- No tracked `.clangd` or `.vscode/*` was found. README already explains the database for clangd. Missing editor recommendations are an optional ergonomics improvement, not absence of editor support. [README](../../README.md)
- Sanitizers are already applied privately to many test targets. `sl_data` is not instrumented in the inspected database; [INFERENCE from the uninstrumented library commands] a sanitized test linked to that static library does not establish instrumentation of the library's own accesses. Some tests have no sanitizer options. ASan requires instrumenting compilation as well as linking its runtime. [CMake target definitions](../../CMakeLists.txt), [ASan usage](https://clang.llvm.org/docs/AddressSanitizer.html)
- Local read-only versions: CMake 4.4.4; Ninja 1.13.2; Apple clang 21.0.0 at `/usr/bin/clang`; PATH clang-format 23.1.4; Homebrew clang-tidy 23.1.3 at `/opt/homebrew/opt/llvm/bin/clang-tidy`; PATH clangd `/usr/bin/clangd`. The guard chooses PATH tools first and Homebrew LLVM as fallback, so even formatter/tidy patch versions differ locally. These are observations, not required versions. CI installs floating Homebrew LLVM. [tool resolver](../../tools/guardrails.py), [CI](../../.github/workflows/check.yml)

## Recommended minimal implementation, in priority order

1. **Make developer feedback predictable before widening lint.** Extend `tools/guardrails.py` with a single explicit compilation-database selection option (default `build` for compatibility) and clear missing-entry diagnostics. Thread it through an applicable `tools/parity/dev.py` lane. Document presets versus canonical gate paths in `tools/parity/agent-tools.md`. Add a read-only doctor report for resolved compiler/formatter/tidy/clangd paths and versions, database presence and tracked-source coverage; no implicit package installs or configure/build side effects. Prefer the existing Apple compiler for native builds; resolve format/tidy from the same declared LLVM release family rather than silently changing compilers. A Homebrew compiler swap must use a fresh build directory and fresh numerical qualification.
2. **Reconcile formatting policy without blanket reformat.** Preferred small rollout: preserve whole-file checks for new files, but for edited files compare formatter output to the staged baseline and reject newly introduced format differences within changed ranges, with a documented explicit whole-file command. Clang-format supports line ranges, but range formatting may expand to surrounding constructs; report patches without applying them. Keep the existing no-auto-write rule and add isolated Git controls for clean partial staging, unrelated pre-existing format debt, newly introduced debt, deletions, renames and paths with spaces. An alternative is a declared baseline-debt manifest, but that adds maintenance and should not precede evidence that range checks are insufficient. [ClangFormat command-line options](https://clang.llvm.org/docs/ClangFormat.html)
3. **Keep staged lint honest.** Retain explicit refusal when the selected main file differs in the worktree for the first implementation; improve its message to explain that formatting uses index bytes and lint needs matching bytes. Do not claim full staged-tree analysis. Supporting partially staged C++ properly needs an isolated index snapshot plus compile-command path rewriting and dependency/config consistency; that is a separate change, not a temporary-file main-source hack. Validate changed included-header mismatch handling before strengthening any staged-tree claim.
4. **Resolve headers and foreign sources explicitly.** For native `.cpp/.m` files require a real exact compile-command match; deduplicate repeated commands deterministically. For headers analyze real includers using database/dependency information, retaining header diagnostics, and report coverage rather than pretending direct header parsing is sufficient. Missing entries must produce actionable “no configured translation unit” output. Keep Stock MinGW/Wine sources in their specialized toolchain workflow; do not append generic `-- -std=c++20` to make native tidy parse Windows helpers. Experiments may use a recorded explicit command or a separately generated database. Start with clear refusal and an explicit opt-in path, not broad automatic inference. [Clang-Tidy](https://clang.llvm.org/extra/clang-tidy/), [clangd header commands](https://clangd.llvm.org/design/compile-commands)
5. **Document local dependency overrides; do not vendor everything.** Retain SDL's imported `SDL3::SDL3` target. Add ignored `CMakeUserPresets.json` with a checked-in example/documentation for local SDL3_DIR/CMAKE_PREFIX_PATH and compiler selection; current `.gitignore` lacks this filename. CMake explicitly distinguishes checked-in project presets from untracked user presets; SDL documents config package consumption. Avoid hardcoding a Homebrew prefix globally. [CMake presets](https://cmake.org/cmake/help/latest/manual/cmake-presets.7.html), [SDL CMake integration](https://wiki.libsdl.org/SDL3/README-cmake)
6. **Offer an isolated full instrumentation configuration after the low-risk tooling changes.** Add a CMake option and separate sanitizer preset that instruments the production libraries exercised by tests and links sanitizer runtimes into executables. Keep existing defaults unchanged initially, preserve resource-pool admission, and establish which tests can run without private data. Never use instrumented builds for performance/parity evidence or signed release packaging. ASan recommends debug information and frame pointers for readable traces. [ASan documentation](https://clang.llvm.org/docs/AddressSanitizer.html)
7. **Optional editor polish.** Add a small `.clangd` selecting the canonical database, or document editor arguments selecting the chosen preset database. Recommend a matching clangd installation without committing machine-specific executable paths. Avoid a second broad lint ruleset in the editor. clangd needs the actual include paths, target and language flags, rather than generic C++20 fallback flags. [clangd design](https://clangd.llvm.org/design/compile-commands)

## Numerical fidelity and retained evidence

Keep `-ffp-contract=off` explicit for every native physics translation unit and probe intended to establish parity. Do not replace it with `-fno-fast-math`: Clang documents different contraction defaults and option-order interactions. Do not introduce fast-math, new reassociation, FMA operations, or x87 emulation based on tooling preference. Existing project standards explicitly require stock grouping and demonstrated mismatch before x87 changes. [Clang floating-point controls](https://clang.llvm.org/docs/UsersManual.html#controlling-floating-point-behavior), [project numerical rules](../../CODING_STANDARDS.md)

Retain current build/evidence directories and `ref/` untouched. New toolchain or sanitizer configurations belong in fresh ignored build trees. Retained hashes and historical records remain historical; tooling edits do not upgrade their completion status. Numerical, compiler or compile-option changes require newly bound evidence under the existing admission and retention workflow. [Agent command guide](../../tools/parity/agent-tools.md)
