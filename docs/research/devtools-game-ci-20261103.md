# Game-specific CI and developer workflow research

Research date: 2026-11-03. Source baseline: `d38d405ff7666e462411d21bbad7cb3563763d84`. Research only: no builds, tests, captures, runner changes, signing or publication performed. The full game goal remains paused. Recommendations below are infrastructure work, not proof of game completion.

## Recommendation

Keep the existing developer entry point, shared resource pool, strict evaluator, native/Stock adapters, retention ledger and release tooling. The useful bounded pass is to repair the hosted runner selection, make onboarding accurate, and give hosted CI an explicitly audited asset-free C++ lane. Improve assertion/instrumentation coverage and structured failure reporting next, without changing the existing complete gate's meaning or running private captures from public CI. [Repository command guide](../../tools/parity/agent-tools.md), [full specification](../specs/full-port-1.0.0.md), [coding standards](../../CODING_STANDARDS.md).

## Confirmed gaps and bounded changes

### P0: repair hosted execution and accurate onboarding

1. Replace the hosted `macos-14` label with a currently supported explicit ARM64 label, such as `macos-15`. The official runner-images announcement says all GitHub macOS 14 images retired on **2026-11-02**; this is already past on this research date. GitHub currently lists `macos-15` as ARM64 with 3 CPUs and 7 GB RAM. Validate the resulting workflow, but distinguish local validation from an actual successful remote run. [Official retirement announcement](https://github.com/actions/runner-images/issues/13518), [current runner specifications](https://docs.github.com/en/actions/reference/runners/github-hosted-runners).
2. Update the root README to point at the agreed full specification and `dev.py` guide. Its current opening says the car factory/physics/track scene are absent and Free Ride stops, contradicting the specification's bounded driving observations. Replace historical claims with a scoped incomplete-status statement, not a new unsupported playable/completion claim. Its raw configure command bypasses shared admission; document a pooled configure lane. Clarify that a clean public clone cannot run the private full gate without local reference resources. [README](../../README.md), [specification starting evidence](../specs/full-port-1.0.0.md), [command guide](../../tools/parity/agent-tools.md).
3. Add explicit hosted job timeout and cancel superseded *hosted* PR runs if desired; do not apply cancellation semantics to private captures/notary/publication. Pin checkout to a verified full commit SHA and disable persisted credentials where no later Git writes need them. Current `@v4` is mutable; GitHub identifies full SHA pinning as the immutable option. Keep no public upload of private assets, captures, PCM, save data or raw game logs. [GitHub secure use](https://docs.github.com/en/actions/reference/security/secure-use).

### P1: execute a genuine asset-free C++ slice in hosted CI

The hosted compilation database is useful for lint, but it does not detect compile/link/runtime regressions. Audit a **small explicit allowlist** of tests and their transitive runtime/source inputs rather than selecting all names ending `_unit`: some unit registrations take `ref/raw` arguments (`road_network_unit`, `road_alignment_unit`, `road_route_unit`) and many resource/VM tests read real game data. `scene_skinning_unit` is one candidate: its test body constructs mesh/palette data itself; it still links `sl_data`, so dependency/side-effect review and a real no-`ref` execution remain necessary before declaring it portable. [CMake registrations](../../CMakeLists.txt), [synthetic scene skinning test](../../tests/scene_skinning_test.cpp).

Expose the selected targets/test names through the existing entry point or a small shared manifest, build only required targets, run CTest with `--no-tests=error --output-on-failure`, and keep serial execution until writable state is audited. Use a hosted budget smaller than the local fixed six-job build: the 3-core/7-GB runner is not the 18-core/48-GiB host described by `iteration.md`. Existing `host-memory` permits are **512 MiB**, not GiB. Do not change live global pool capacity or lower disk/memory floors to make hosted work fit. Bound admission, execution and logs; report admission refusal distinctly from test failure. [Shared admission](../../tools/parity/iteration.md), [pool CLI](../../tools/parity/resource_pool.py), [CTest options](https://cmake.org/cmake/help/latest/manual/ctest.1.html).

Meaningful verification: run this lane in an isolated checkout with `ref` absent; prove a missing/misspelled test selector fails; inject a failed expectation and verify CI fails; verify only the listed targets/tests run. Do not use fabricated game resources or skip missing data and report green. A public slice is an early regression signal and cannot replace the complete private gate.

### P1: keep assertions alive and instrument code actually under test

Audit C++ test targets systematically: Release is the gate's selected configuration, `-UNDEBUG` appears on only selected targets, and some assertion-based tests lack it (for example `tests/object_sound_test.cpp`/`object_sound_test` and `tests/camera_device_body_test.cpp`/`camera_device_body_test`). Preserve ordinary production release semantics while ensuring every test's checks execute. Prefer a small test-target helper applied to actual test executables, rather than globally undefining `NDEBUG` for the player application. Retain custom `CHECK` tests as they are. [CMake targets](../../CMakeLists.txt), [object sound test](../../tests/object_sound_test.cpp), [camera body test](../../tests/camera_device_body_test.cpp).

Sanitizer flags on a test linked to `sl_data` instrument its test translation units, not already compiled shared library code. Do not describe this as whole-engine sanitizer coverage. A later opt-in sanitized build tree should instrument shared production libraries and consumers together, keep UBSan fail-fast, retain debug symbols/frame pointers for diagnostics, and avoid mixing its objects with the normal Release tree. ASan requires compilation instrumentation and final executable runtime linkage; Clang recommends `-fno-omit-frame-pointer` for better reports. [ASan documentation](https://clang.llvm.org/docs/AddressSanitizer.html), [UBSan documentation](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html).

Meaningful verification: an isolated assertion-failure control compiled through the same test policy must fail in Release; a small out-of-bounds or UB control reached inside a sanitized library must fail nonzero. Keep these temporary faults outside production/game paths. No sanitizer pass demonstrates paired physics/VM parity.

### P2: make failing stages and evidence easier to review

Keep the existing fail-fast gate, but add stage names and retain an explicit failed stage plus unexecuted stages in any wrapper report. Avoid a second hand-maintained list of suites: `dev.py corpus_commands()` currently parses `check.sh` lines, so refactoring shell execution can silently change the corpus lane unless its parser/tests are updated together. The existing experiment result helper already supports ordered named stages, expected refusal exits, pending/final failed results and retention accounting; reuse its semantics rather than build another evidence framework. [Developer entry](../../tools/parity/dev.py), [experiment contract](../../tools/parity/experiment_result.py), [command guide](../../tools/parity/agent-tools.md).

Optionally emit CTest JUnit into a fresh private retained result tree. It is available from CMake 3.21 while this project's minimum is 3.20, so feature-detect or explicitly raise/document the prerequisite first. CTest overwrites an existing JUnit path; do not reuse historical paths. Preserve the full invocation status: later standalone checks cannot repair a failed full gate. Per-test TIMEOUT can isolate a hung test, but must be chosen from actual workload knowledge and does not replace pool-level process-tree cleanup. [CTest JUnit and no-tests options](https://cmake.org/cmake/help/latest/manual/ctest.1.html), [test TIMEOUT](https://cmake.org/cmake/help/latest/prop_test/TIMEOUT.html), [full specification](../specs/full-port-1.0.0.md).

Bind useful run metadata to source commit plus dirty input hashes, compiler/linker/Python/CMake/Ninja/LLVM tool versions, SDK/Xcode identity, architecture, configuration and resolved SDL/JPEG/PNG versions. Existing evidence-index and Jev packet helpers already enforce file/hash/exact assertion bindings; add ordered attempts instead of replacing old evidence. A metadata recorder should not claim reproducible builds merely because it records versions. [Evidence guide](../../tools/parity/agent-tools.md), [current bindings](../../tools/parity/session-evidence.json).

### P2: document one supported toolchain before adding dependency managers

CMake requires SDL **3.4.0**, while README only says SDL3; Homebrew dependencies and LLVM are unversioned in CI. Document the actual compiler/SDK and tested dependency range, record their resolved identities, and choose a compatible formatter/tidy major so a Homebrew update does not unexpectedly redefine checks. A Brewfile improves discoverability but is not a lockfile. CMake presets can share configure settings; use a schema supported by the project's minimum CMake, ignore `CMakeUserPresets.json`, and keep builds launched through the shared pool. Avoid forcing a new manager/vendor tree in this bounded pass. [CMake configuration](../../CMakeLists.txt), [workflow](../../.github/workflows/check.yml), [official presets documentation](https://cmake.org/cmake/help/latest/manual/cmake-presets.7.html).

## Numerical, scheduler and release constraints that remain acceptance work

Keep `-ffp-contract=off`, stock float widths and operation grouping in every profile. Do not enable fast math/FMA or loosen comparisons to make CI pass: Clang documents that fusion changes rounding and fast math changes assumptions. Exact physics/VM comparisons, repeatability and field-specific tolerances require actual Stock evidence and replay controls; output signatures from the existing repro helper are only verdict/output repeatability. [Coding standards](../../CODING_STANDARDS.md), [Clang floating-point controls](https://clang.llvm.org/docs/UsersManual.html#controlling-floating-point-behavior), [D5/testing specification](../specs/full-port-1.0.0.md).

Do not parallelize the complete CTest suite, enable live protocol 2, alter capture focus/audio behavior, migrate/reset admission state, or claim full descendant containment. The repository explicitly records escaped-session and guardian boundaries, and broader throughput/responsiveness qualification is still open. Synthetic failure controls are useful infrastructure evidence; actual capture/runtime qualification belongs to the paused game work. [Iteration limits](../../tools/parity/iteration.md), [pool implementation](../../tools/parity/resource_pool.py).

Keep the existing release tools and their unknown-upload/retry defenses. A standalone app must close SDL/native dependency paths, use normal external saves/settings, and pass clean-machine installation, Gatekeeper/notarization, input/audio, save/reload and app-replacement tests on the **exact** signed DMG. SDL's macOS documentation distinguishes a bare app bundle from a distributable bundle including dependencies; it does not qualify this game's selected macOS support. No tag-triggered public release should be added before the full acceptance gate. Actual credentials/service submissions, reconciled content, clean-system access and downloaded-release acceptance remain deferred. [SDL macOS guidance](https://wiki.libsdl.org/SDL3/README-macos), [existing release workflow](../../tools/release/README.md), [release prerequisites](full-port-release-prerequisites.md), [full release specification](../specs/full-port-1.0.0.md).
