## Minimal implementable policy

### P0 — one staged-safe checker and reproducible installation

Add root `ruff.toml` with non-preview `lint.select = ["E9", "F63", "F7", "F82"]`, explicit excludes for `ref/`, `build/`, `build-*/`, `local/`, `.scratch/`, and evidence/generated directories. Use `force-exclude = true`, `fix = false`, and an exact `required-version` matching the installed dev tool. Start with these high-signal error families; do not enable ALL, line-length, unused-import cleanup, import sorting or upgrade rewrites. Ruff supports configuration, stdin filenames and exclude controls in its [configuration reference](https://docs.astral.sh/ruff/configuration/), with version constraints in [settings](https://docs.astral.sh/ruff/settings/#required-version). Target version must describe a documented, actually qualified Python floor, not simply the newest interpreter on one host.

Extend `tools/guardrails.py` to run pinned Ruff against the existing blob bytes via stdin and an explicit repository config/filename. Keep AST parsing for exact encoding/syntax handling and keep `-I` on Python subprocesses. `ruff` can be invoked as a separately installed executable; there is no need to turn the scripts into a package or add Poetry/uv/pytest. Use timeouts, captured diagnostics and nonzero refusal for missing or wrong tool versions. Never `--fix`, write/stage files, use working bytes in place of the blob or run an imported target to lint it. Decide and test whether staged configuration changes require the staged config in a scratch file or an explicit working/index equality refusal; silently reading a different working config defeats staged correctness.

Create a small `requirements-dev.txt` with exact selected Ruff and Pillow versions (or separate lint and imaging requirement files if keeping lightweight lint installation matters). Add `.venv/` and `.ruff_cache/` to `.gitignore`. Document `python3 -m venv .venv`, `.venv/bin/python -m pip install -r requirements-dev.txt`, activation and hook installation in README/agent-tools. Python [venv](https://docs.python.org/3/library/venv.html) gives isolated site-packages; [isolated mode](https://docs.python.org/3/using/cmdline.html#cmdoption-I) excludes user site, script/current-directory injection and Python environment overrides, but does not mean that a selected venv cannot supply its installed dependencies. Avoid `pip install --user` as the documented dependency solution for commands using `-I`.

Select exact supported versions during implementation, with local/CI agreement and an explicit update procedure. Read-only host observations here: Python 3.15.0, Ruff 0.17.0, ShellCheck 0.11.0; shfmt was not found on PATH. These observations are not tested compatibility promises or a recommendation to adopt Python 3.15 unconditionally. CI should select the chosen Python version and consume the same requirements file. Preserve an independent lightweight lint step that does not need private `ref/` or a configured native build; existing C++ checks can retain their compilation database prerequisite.

Meaningful validation: in scratch Git repos, exercise staged undefined-name rejection, valid-byte acceptance, bad-working/good-index and good-working/bad-index cases, spaces/non-ASCII paths, add/rename/delete, missing tool, version mismatch, subprocess failure, staged config mismatch, and protected `ref/` changes. Assert exit status, diagnostic identity and untouched working/index bytes. Run actual tool processes; do not assert implementation source strings. Also test protected deletions explicitly: today's ACMR diff filter omits them, so a policy intended to reject every `ref/` change needs a separate all-status protected-path check.

### P1 — shell checking with an explicit dialect map

Add ShellCheck to the same guardrails dispatcher for tracked shell blobs and the extensionless hook. Feed bytes through stdin, choose `sh` for the hook and Bash for confirmed Bash entrypoints (including the no-shebang container payload), and pass explicit filenames/dialect context for useful diagnostics. Inspect all 45 scripts before declaring a universal shell version: macOS `/bin/bash` and Linux Bash need not expose identical features. Check embedded workflow shell through the existing actionlint route; YAML is not a standalone shell script.

Start with changed files and reviewed, narrow suppressions with reasons. Missing ShellCheck must fail in CI and in an enabled hook, with an installation hint. Do not execute Docker, MinGW, wine, input injection or capture scripts to check syntax. A shell checker cannot validate a Windows command line passed through Wine, heredoc Python syntax, shared resource admission or foreground/audio safety.

Add scratch-hook controls for a genuine unquoted expansion and clean quoted control; include POSIX-vs-Bash behavior and a no-shebang Bash payload. Verify no local script execution or byte rewrites. Add exact tool-version documentation and CI installation checks. No additional hook manager is needed.

### P2 — formatter and editor consistency without repository churn

Ruff formatting is useful, but make it opt-in for a small explicit path allowlist of new/maintained files initially. Gate only that allowlist with `ruff format --check`; non-allowlisted Python still receives high-signal lint. Keep single quotes if chosen after reviewing nearby style, disable docstring code formatting, and leave import sorting off. The [Ruff formatter](https://docs.astral.sh/ruff/formatter/) documents check mode, code formatting and suppression. Treat `# fmt: off` blocks for byte-sensitive fixture strings as reviewed exceptions; do not rewrite numeric tables, binary/hex fixtures, generated payloads or embedded source wholesale. Formatter output is a reviewable patch, not evidence of semantic equivalence.

Optional shfmt can follow the same small allowlist. Upstream [shfmt manual](https://raw.githubusercontent.com/mvdan/sh/master/cmd/shfmt/shfmt.1.scd) documents check/diff modes, dialect selection and EditorConfig interaction; avoid `-w` in gates and avoid blanket simplification. Shell heredocs and embedded Python deserve byte review before acceptance.

Add a narrow `.editorconfig`: Python four-space indentation, native source two spaces, LF for explicitly owned script/config paths. Avoid global trailing-whitespace removal/final-newline insertion over retained evidence or fixtures. [EditorConfig](https://editorconfig.org/) is editor guidance, not proof of lint. Add `.gitattributes` only after a `git ls-files --eol` audit, using explicit script patterns (`text eol=lf`) and `-text` for confirmed byte-exact fixture paths. Git's [attributes documentation](https://git-scm.com/docs/gitattributes) explains checkout/index conversion; do not introduce blanket `* text=auto` or run mass `git add --renormalize` in this task.
