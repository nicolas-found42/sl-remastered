# Player analog input

`PlayerInputState::sampleAxis` now distinguishes digital/analog axis type from physical device class. Normalized mouse axes use the direct mouse response; non-mouse analog inputs use the Stock lag response. A missing physical class remains an explicit Gap. This is an input implementation slice, not controller hardware or paired gameplay qualification.

The older reader is `0054d830`. Newer analysis identifies `00565b60`, and `004d28d0` case `0x43` calls it for ordinary Player controls while keeping scripted override and invalid-axis handling separate. Newer sample/type/device-class helpers are `00544830`, `005447e0` and `005448d0`; the older counterparts are `00557430`, `00557990` and `00558130`.

Both selected references use a strict one-tenth source-range movement threshold before a mapping of the other axis class takes ownership. Mouse class `2` applies the mapped sum directly. The non-mouse analog branch uses distance threshold `0.021`, signed lag `0.02`, and nearby interpolation factor `0.3`. The newer mouse sampler `00543f70` also confirms normalized relative motion `(delta / frame duration) * 0.005`, clamped to `[-1,1]`, with separate button values.

The new public `PlatformInput::deviceKind` exposes the existing detected device class. `GameWorld` passes that reader to Player input alongside sample and axis-type readers. Digital mappings retain their existing ramp smoothing; analog mappings retain the same-frame cache and response curve. Unknown class or unsupported force-smoothing cases return a diagnostic instead of invented zero input. Host reader failures leave axis and mapping history unchanged.
